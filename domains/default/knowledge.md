## Windows 路径、盘符与编码

工作目录是 `D:\code` 这类盘符路径时，shell 用 Git Bash，要写成 `/d/code`；给 Windows 程序传路径要写成 `D:\code`（或用 `cygpath -w` 转换）。

- 路径含空格必须加引号。含中文一般没问题，但生成 `.bat`/`.ps1` 脚本时不要写非 ASCII 路径——脚本编码与系统代码页不一致会吞掉文件名。
- 读文本文件默认按 UTF-8；读到乱码（`锟斤拷`、`????`、成片 `\u00e4`）说明源文件是 GBK/GB18030，按 GB18030 重读，不要当成损坏。
- 换行：Windows 常见 CRLF。做文本比对/哈希前先确认要不要归一化，否则同样的内容会算出不同的哈希。

## 命令执行：三种 shell 不要混用

| 场景 | 用什么 | 注意 |
|---|---|---|
| 常规命令、管道、git | `shell.run`（默认 bash） | `C:\x` 会被当转义，改 `/c/x` |
| 需要 Windows 专有（注册表、服务、COM、.NET） | PowerShell 工具 | 不要从 PowerShell 里调 bash 绕路 |
| 需要 cmd 内建（`dir /b`、`copy /y`） | `cmd /c` | 不要用 `start` 启动 GUI 进程 |

**不要**用 `sleep` 等待。要等就轮询检查条件，或用超时机制。长时间命令放后台跑，别阻塞在那里。

## 读文件与搜索：先选对工具

- 看某个文件的内容 ⇒ 文件读取工具，不要 `cat`（`cat` 会在输出里丢失行号，也无法限制行数）。
- 找"哪个文件里有某个字符串" ⇒ 搜索工具（ripgrep），不要 `find | xargs grep`。
- 找"名字符合某个模式的文件" ⇒ glob，不要 `ls -R`。
- 需要精确行号用于后续编辑 ⇒ 读取时带行号。

判断要不要先搜：不确定文件在哪、不确定那个函数叫什么、不确定有没有现成实现——先搜，别猜路径。

## 网络请求：区分"一次抓取"与"有状态的浏览"

| 需求 | 用什么 |
|---|---|
| 取一个 URL 的响应（看头、看正文） | 一次性 HTTP 请求 |
| 多步交互（登录后访问、保持 Cookie、提交表单） | 无头浏览器的会话能力 |
| 只是探活/看端口 | TCP 探测，不要发 HTTP |
| 解析域名 | DNS 查询，不要 ping（ICMP 常被禁） |

关键区别：**一次性请求不带 Cookie**。需要登录态就必须开会话，否则拿到的全是未登录页面。反过来，只取一个静态页面时开会话是浪费。

本基座**不执行 JavaScript**。拿到的 HTML 是服务端原始输出；SPA 页面在正文里可能一片空白，这时候要说清"这个页面靠 JS 渲染，我拿到的是空壳"，而不是报告"页面没有内容"。

## 大文件与大输出：先缩范围，再取全量

输出超过几千行时不要整份塞进上下文：

1. 先看结构（行数、列名、前后各几行、有没有明显的分段）。
2. 按需要缩范围（只取匹配行、只取某几列、只取时间窗口）。
3. 确实需要全量时，说明为什么需要，并接受它占掉大量预算。

日志类数据优先用聚合（按错误码计数、按分钟统计）代替逐行阅读。

## 时间、时间戳与"今天"

- 不要自己心算时间戳或日期差。要 Unix 时间就问系统（`date +%s`），要日期加减就用工具算。
- "最近三天"这类相对时间，先确认基准是本地时区还是 UTC，再算边界。
- 文件时间戳（mtime）不等于内容修改时间（复制/解压会重置）。判断"哪些是新改的"时，优先看版本控制而不是 mtime。

## 不可逆操作的确认口径

以下动作**必须**先说明再执行，且要给出退路：

- 删除（文件、目录、数据库记录、云端资源）
- 覆盖已有文件
- 发布/上线/对外发送（消息、邮件、PR、部署）
- 修改生产环境或共享环境
- 花钱（购买、扩容、调用计量 API）

确认时要说清三件事：**具体影响哪些对象**（列出路径/名称，不要只说"清理临时文件"）、**有没有备份**（在哪）、**怎么撤回**。

个人目录（桌面、下载、文档）的批量操作，第一遍只做扫描出清单，不动文件。

## 写代码前的三个检查

1. 这个功能是不是已经存在？先搜，避免重复实现。
2. 改动会影响谁？找调用方，别只改定义处。
3. 怎么验证？没有验证手段的改动先补验证，再改逻辑。

改完不要只说"改好了"——要说明改了哪个文件、哪段行为变了、用什么方式确认的。编译通过不等于逻辑正确，测试通过不等于覆盖了这条路径。

## 遇到"看起来能跑但结果不对"

这类问题最耗时，按这个顺序查：

1. **先确认输入**：你以为传进去的值，实际是什么？打出来看。
2. **再确认中间态**：链路中间那一步的输出对不对？不要跳过。
3. **再看边界**：空值、0、负数、超长字符串、并发、时区、编码——八成在这里。
4. **最后才怀疑依赖/环境**：版本、配置、缓存、残留进程。

不要反过来（先怀疑环境），那会浪费大量时间在重装和重启上。
